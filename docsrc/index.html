What it is

multiversectl gives a system that spans several repositories as many complete, working copies as you need, on one machine. Each copy is a universe, numbered or named after the branch it checks out, and it has all of it: a git worktree of every repository, every app running as its own compose project, its own data, and hostnames that open from any device on your network. So a branch to review, a migration to try or an agent to let loose each gets a whole environment, while yours keeps running.

It namespaces instead of virtualizing. A new universe is a worktree and a compose up: seconds, on the daemon and image cache you already have, from the compose files you already run. The addresses are the part most tools leave to you: one shared proxy routes by hostname, and each universe hands its own URLs and origins to the services that check them, so logins, callbacks and CORS work in every copy.

What it is not

Knowing where it stops saves trying it for the wrong job.

It is notBecauseFor that, use
A sandbox or a VMUniverses share your kernel, daemon and user: one can fill the disk or reach another's containers. They are copies you trust, not a boundary.A VM, or a container sandbox for untrusted code
A replacement for docker composeIt describes no containers. It reads your compose files and adds only routing and names, so they keep working without it.The compose files you have
A rebuild-on-save loopWhat reloads in a universe is what your compose files already do: a bind mount and a dev server.Your dev server; Tilt or Skaffold on Kubernetes
A deployment or production toolIt runs on one machine, for development. Nothing it does belongs on a server others depend on.Your deployment pipeline
A preview service on the internetA universe answers on this machine or its network, not to the outside world, and is made by you, not by CI.A preview-environment service
An agent runnerIt gives an agent a whole environment to work in; it does not start, prompt or supervise the agent.Your agent, or a worktree manager, pointed at a universe
A way to share one database among copiesEach universe runs its own services, data included. That keeps branches apart, and it is what the machine's memory has to hold.Fewer universes, or lighter services in an overlay
