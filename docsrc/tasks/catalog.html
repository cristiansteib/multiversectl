Set up your root catalog

# asks: an existing repository, a new private one, or local only
$ multiversectl init
# or say it with flags
$ multiversectl init --create multiverse-index
$ multiversectl init --repo git@example.test:me/multiverse-index.git
$ multiversectl init --local ~/multiverse-index

--create uses the GitHub CLI and makes the repository private; --public is the only way to make it public. Without gh installed and logged in, create the repository yourself and pass --repo. A repository that already holds a catalog.yaml is used as it is. Creating a repository and pushing both ask first; --yes accepts them for scripts.

Nest another catalog

# asks which catalog it goes in, and whether it gets a repository of its own
$ multiversectl catalog create acme
# or decide up front
$ multiversectl catalog create acme --new-repo acme-index --at /
$ multiversectl catalog create personal --same-repo --at /
# link a catalog someone else already keeps
$ multiversectl catalog add catalog git@example.test:acme/multiverse-index.git --at /

The new catalog can live as a file in its parent's repository, in a repository you already have, or in a new private one.

List a workspace

$ multiversectl catalog add workspace git@example.test:acme/api-workspace.git --at acme
$ multiversectl catalog tree
index
  acme                     catalog
    api                    workspace  git@example.test:acme/api-workspace.git multiverse.yaml

The name comes from the manifest's metadata.name unless --name says otherwise. Writes go to the file that owns the catalog you picked, are committed, and, in a remote repository, pushed after you confirm. If someone pushed first the command says so and leaves your copy clean. catalog rm <path> takes an entry out; what it pointed at is untouched.

Install only what this machine needs

# one workspace, or everything under a catalog
$ multiversectl install acme/api
$ multiversectl install acme personal/fichero
# no path: pick from a list
$ multiversectl install
$ multiversectl workspaces
$ multiversectl use acme-api

Each workspace is cloned under ~/multiverse/<catalog path> (--base changes it) and recorded as acme-api. Installing does not switch the current workspace, and one that is already installed is skipped. If two installed workspaces would publish the same proxy port or share a proxy network, install says so, because only one proxy can bind it. catalog sync fetches every catalog repository again; uninstall <name> forgets a workspace and leaves its files.
