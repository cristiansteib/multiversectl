Set up your root catalog

# asks: an existing repository, a new private one, or local only
$ multiversectl init
# or say it with flags
$ multiversectl init --create multiverse-index
$ multiversectl init --repo git@example.test:me/multiverse-index.git
$ multiversectl init --local ~/multiverse-index

--create uses the GitHub CLI and makes the repository private; --public is the only way to make it public. Without gh installed and logged in, create the repository yourself and pass --repo. A repository that already holds a catalog.yaml is used as it is. Creating a repository and pushing both ask first; --yes accepts them for scripts.

Nest another catalog

# asks which catalog it goes in, and whether it gets a repository of its own
$ multiversectl catalog create acme
# or decide up front
$ multiversectl catalog create acme --new-repo acme-index --at /
$ multiversectl catalog create personal --same-repo --at /
# link a catalog someone else already keeps
$ multiversectl catalog add catalog git@example.test:acme/multiverse-index.git --at /

The new catalog can live as a file in its parent's repository, in a repository you already have, or in a new private one.

List a workspace

$ multiversectl catalog add workspace git@example.test:acme/api-workspace.git --at acme
$ multiversectl catalog tree
index
  acme                     catalog
    api                    workspace  git@example.test:acme/api-workspace.git multiverse.yaml

The name comes from the manifest's metadata.name unless --name says otherwise. Writes go to the file that owns the catalog you picked, are committed, and, in a remote repository, pushed after you confirm. If someone pushed first the command says so and leaves your copy clean. catalog rm <path> takes an entry out; what it pointed at is untouched.

Install only what this machine needs

# one workspace, or everything under a catalog
$ multiversectl install acme/api
$ multiversectl install acme personal/fichero
# no path: pick from a list
$ multiversectl install
$ multiversectl workspaces
$ multiversectl use acme-api

Each workspace is cloned under ~/multiverse/<catalog path> (--base changes it) and recorded as acme-api. Installing does not switch the current workspace, and one that is already installed is skipped. If two installed workspaces would publish the same proxy port or share a proxy network, install says so, and so does doctor later, because only one proxy can bind it. catalog sync fetches every catalog repository again; uninstall <name> forgets a workspace and leaves its files.

Start a project from a manifest you already have

# asks which catalog it goes under, and which repository holds it
$ multiversectl catalog create acme --manifest ./acme.yaml
# or say it all up front
$ multiversectl catalog create acme --manifest ./acme.yaml --at / --new-repo acme-org/multiverse

The new repository gets a catalog.yaml that lists the manifest, copied in as multiverse.yaml, so the project is its own index and its own workspace. With --same-repo both go in the parent's repository instead. It warns about a machine-specific spec.root, and about an overlays/ directory next to the manifest, which is not copied. A repository that already has a catalog is refused: use catalog add workspace there.

Make a project others can join

Give the project one repository that is both its index and its own workspace definition. The catalog can list that workspace with no repo, because a reference stays in the repository it is written in, and can link deeper catalogs when the project needs them.

# catalog.yaml in acme/multiverse
apiVersion: multiverse/v1alpha1
kind: Catalog
metadata:
  name: acme
spec:
  workspaces:
    - name: acme                    # acme/acme installs as acme
      source: {path: multiverse.yaml}   # this repository's own manifest

Anyone then needs one command; the source can be owner/repo, any git URL, or a path to a local checkout. On a machine with no root catalog yet it asks where to keep one first.

$ multiversectl add acme/multiverse --install
$ multiversectl new 1
$ multiversectl up 1

owner/repo means GitHub; give a full URL for anywhere else. A repository with only a multiverse.yaml is listed as a workspace, and adding the same repository twice changes nothing. A catalog and a workspace with the same name are installed as one directory and one name, so the project above is just acme. Drop machine-specific lines such as an absolute spec.root from a manifest you share: install chooses where it goes.
