Let a service declare its own hostname

Put a label on the service in its own compose file: the key names the host, the value is the container port.

services:
  app-dev:
    labels:
      multiverse.host.app: "4200"   # app-u3.<domain> -> port 4200

With no labels at all, a service exposing exactly one port is already reached at the app's own name. See Labels and variables for entrypoints and aliases.

Keep a service's published port

Universes drop every published host port, so two copies never collide. A service that genuinely needs one asks to keep it:

services:
  db:
    ports: ["5432:5432"]
    labels:
      multiverse.publish: "true"

Or, without touching the repository, publish: [db] on the app in the manifest. Only one universe can hold that port at a time.

Choose where exec and run go

An app with several services makes universe exec and universe run ask for --service every time. Name the one you almost always want:

# multiverse.yaml, on the app
defaultService: web

--service still wins. When the app lists services, the default must be one of them.

Run optional services on demand

# multiverse.yaml, on the app
optional:
  - name: celery
    services: [worker, beat]
$ multiversectl universe up 3 api --with celery

The group name is activated as a compose profile too. Comma-separate several: --with celery,mail.

Configure what depends on the universe

A universe's hostnames do not exist until it does, so anything built from them — trusted origins, allowed hosts, CORS, a front-end's API base URL — is asked for with a label on the service that needs it:

services:
  web:
    labels:
      multiverse.env.DJANGO_ALLOWED_HOSTS: hosts
      multiverse.env.DJANGO_CSRF_TRUSTED_ORIGINS: origins
      multiverse.env.API_BASE_URL: url:devapi

These win over the service's own environment: and over any env_file:, which is how a static list in a committed .env stops being what the universe runs with. The sources, and why it is a label rather than a variable reference, are in Labels and variables. For a repository you cannot change, the app's inline overlay: does the same from the manifest:

apps:
  - name: api
    repo: api
    overlay:
      services:
        web:
          environment:
            DJANGO_CSRF_TRUSTED_ORIGINS: "${MULTIVERSE_ORIGINS}"
            DJANGO_ALLOWED_HOSTS: "${MULTIVERSE_HOSTS}"

multiversectl universe env <universe> prints every variable a universe passes.
