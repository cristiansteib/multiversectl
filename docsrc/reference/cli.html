Every command

Everything that acts on a universe lives under universe, which u shortens: multiversectl u new 3 is multiversectl universe new 3. That is the lifecycle (new, checkout, up, down, rm, ls, status, urls, env, run, exec) and doctor, which looks after them. What acts on the whole machine rather than on one multiverse lives under system: the shared proxy, prune across every multiverse, the footprint of what this tool put on the disk, and forget and reset. The tree of multiverses and catalogs lives under catalog: an entry is a multiverse or another catalog, and listing, adding, making, removing and updating work the same on both. Starting one is start; there is no separate install. status, server, init, completion, self-update and version stay at the top level. A command's aliases are listed beside it in multiversectl --help.

CommandWhat it doesExample
catalog list [node-path]Show the catalog as a tree (alias ls; a bare catalog shows its help), or the part under a node. Multiverses already installed are marked, and a layer that cannot be read is listed as unavailable with the reason. --fetch refreshes first, -o json is for scripts, --from shows another catalog.multiversectl catalog list acme/backend
catalog add <owner/repo | url | path>Put a multiverse in the catalog, in the place you pick: a repository with a catalog.yaml is linked as a catalog, one with only a multiverse.yaml as a multiverse; a local checkout is added by its origin; a manifest file goes into a repository (--same-repo, --repo, --new-repo). Where to put it is asked, with the repository each choice writes to; --at names it (a wrong or empty one lists the places), --yes means the root.multiversectl catalog add acme/multiverse
catalog rm <path>Remove an entry from the catalog that holds it. What it points at is untouched, and a multiverse installed from it stays installed.multiversectl catalog rm acme/billing
system footprintList everything multiversectl put on this machine and the command that removes each piece, in a safe order: the web server and proxy that may be running, every universe (with its containers, volumes and worktrees), the clones of your repositories, branches left behind, the configuration and caches, shell completions, and the programs. Anything that would lose work that exists nowhere else, such as uncommitted changes, commits on no remote or a volume's data, is marked. It removes nothing. --script prints only the commands; -o json is for scripts. Run it before system reset, which makes multiverses unknown to it.multiversectl system footprint
system forget <multiverse>Stop tracking a multiverse on this machine; its files stay on disk. Takes the name or the catalog path.multiversectl system forget billing
system resetForget this machine's root catalog and every installed multiverse, to start again from another root. Lists them and asks; deletes no file, checkout or universe. Warns about multiverses that still have universes.multiversectl system reset
catalog new [dir | name]Make a multiverse or a catalog and list it; it asks which (--type multiverse|catalog). For a multiverse it guides the setup: choose its repositories (the checkouts beside it, a search through your GitHub or GitLab repositories, or pasted URLs), where its own repository lives (a new private one under any account you can create in, an existing one, or only here), where to list it in your catalog, and whether to start it. Writes multiverse.yaml and an AGENTS.md describing the multiverse and the tool, commits and pushes after you confirm. For a catalog the argument is its name: a file in its parent's repository (--same-repo), an existing repository (--url) or a new private one (--create). Flags answer every question: --name, --repo [name=]url (repeatable; name= sets the name it has in the manifest), --scan, --create owner/name (or a full URL) with --provider github|gitlab and --host for a self-hosted instance, --url, --local, --public, --at, --no-link, --no-install, --yes.multiversectl catalog new --scan --create acme-org/multiverse
catalog update [multiverse ...]Fetch the catalogs, fast-forward each multiverse's manifest from where it was installed, and clone the repositories the new manifest lists (up to four at a time, with a line of progress for each). Refuses a manifest with local changes. It also fast-forwards the shared clones (what secrets are made from), leaving one with changes, on another branch or ahead of origin alone and saying why.multiversectl catalog update
universe new [number|name]Create a universe on branches of its own: one worktree per repo, secrets and state. Alias create. In every repository it starts a branch that exists nowhere (in the clone or on origin) from the base; if one exists nothing is created and every clash is listed. With no name the next free number is used, stepping over a number whose branch a removed universe left. --branch (repeatable) names the new branch, a bare name for every repo or repo=name; --base starts it elsewhere, the same way. --note records why it exists.multiversectl universe new fix/login
universe checkout [branch]Create a universe on a branch that already exists, to work on or review it. Alias co. It checks the branch out where it exists, named after it (--name for another); a repo without it gets a new branch of that name, or with --only-existing stays on its base, detached. --repo (repeatable) names a different branch for one repo. A branch checked out elsewhere, or that exists nowhere, is refused. With no branch it offers the ones there are. Removing it never deletes the branch.multiversectl universe checkout fix/login
universe up <universe> [app ...]Start a universe, all apps or only those named. --with adds optional service groups. Alias start.multiversectl universe up 3 api --with workers
universe down <universe> [app ...]Stop a universe; keeps data and checkouts. Alias stop.multiversectl universe down 3
universe note <universe> [text] [--pr url]Say what a universe is for and which pull or merge request its work is going to. Both are kept with the universe and shown by ls, status, -o json and the web page, so a person or another agent finding it later knows what it is doing. With neither text nor --pr it prints what is there; --clear empties both. universe new --note sets the text when it is made.multiversectl universe note 3 "fixing the login redirect" --pr https://github.com/acme/api/pull/42
help [command] [--tree] [--flat]Help about one command; with --tree, every command, nested under the one it belongs to, with the aliases each answers to in brackets and a line on what it does. It reads the commands this binary has, so it cannot disagree with it. --flat (which implies --tree) prints one full command per line, to grep.multiversectl help --tree
start [source]From nothing to something running: installs the source, picks the universe — the one named with -u, the only one there is, or a new one — creates it if it has to, starts it, and prints its addresses. A source is read in this order, and what it was taken for is said: a node in your catalog, a path, a git URL, then owner/repo. owner/repo:name picks one of the multiverses a repository defines (multiverse.yaml and multiverse/*.yaml); a repository with a catalog is read as one, so no root catalog is needed. A repository that defines no multiverse but has a compose file runs as itself, named after the repository (with its owner in front if that name is taken; --as names it). A multiverse already installed is used as it is. With no source it uses the one -m names or the folder you are in, else you pick from your catalog. Where it goes is asked, with ~/multiverse/<name> prefilled, unless --root, --base or --yes say. --open opens the first address. Several universes and no -u is a question at a terminal and an error in a script. A catalog node installs every multiverse under it: --install-only stops after installing, and --exclude <path> (repeatable) leaves out a multiverse or a whole branch. A catalog repository that does not answer within 20 seconds (MULTIVERSECTL_CATALOG_TIMEOUT) is shown as unavailable, and the rest of the tree stays usable; one fetched before is read from its last copy and marked as not refreshed. Catalogs are read at the same time, and the web view shows each one's state as it answers.multiversectl start acme/multiverse
universe sync [universe]Bring a universe's code up to date. A universe's checkouts keep the commit they were made from, so a fix that reached main afterwards is not in them. sync fetches and moves each checkout forward when that loses nothing, saying what it did per repository. A checkout with uncommitted changes is never touched; one with commits of its own is left alone unless --merge merges the branch in. --all does every universe. It re-reads the compose labels, so addresses follow; restart the universe to run the new code. universe ls -o wide and universe status say which checkouts are behind.multiversectl universe sync 1
universe rm <universe>Destroy a universe: worktrees, containers, volumes and state. Uncommitted work in a worktree stops it until --force. Asks first; deletes the branches it started when every commit is elsewhere, and keeps one holding unpushed work; --yes skips. Aliases remove, destroy.multiversectl universe rm 3 --yes
universe lsList universes under a header naming the multiverse, its root, its multiverse.yaml, where it came from and the universes folder. Then a table per universe: a row per address with its app and branch, the forwarded address beside it when there is one, and a row for each repository checked out with no services. -o wide is everything else — the service behind each address, what is on, what is off and why, the host ports it publishes — and an on disk block of worktrees, compose projects and volumes. -o json is a compact one-line document for a script or an agent, -o json,wide the whole detail, -o list one line per universe; they combine with commas. universe ls <universe> shows one. Alias list.multiversectl universe ls -o wide
universe statusOne line per universe (-o json gives the compact document of ls): whether it is running, partial, stopped or only created, how many of its services are up, when it was last started, its branches and note. ls has the detail per app.multiversectl universe status
universe urls <universe>Print a universe's URLs, one per line.multiversectl universe urls 3
server start|stop|restart|status|open|pairRun the web view in the background, end it, restart it on the installed build (same options, same link), say where it is, or open it in the browser (starting it first if needed). The view is the separate multiversectl-server program, found beside this one or on the PATH; it is live and can start, stop, create and remove universes, and opens from a link carrying a token that start and status print. start takes --addr (port 0 picks a free one, and a port another process holds is replaced by the next free one), --open, --read-only and --expose (listen on every interface, for another machine on the network). pair gives that machine a six-digit code to open the page with instead of the link: one machine, once, five minutes.multiversectl server start --open
statusHow this machine stands, and what needs attention first: the root catalog (and whether it is marked and readable), each installed multiverse with its drift and how many universes it has and how many run, the shared proxy and the web server, anything doctor warns about, and universes running without the proxy. Offline and quick; --fetch compares with the remotes and looks for a newer release; -o json is for scripts. universe status has the detail of each universe.multiversectl status --fetch
system pruneRemove universes across every installed multiverse (-m narrows it to one), the way universe rm does. It lists what it will do and keeps, saying why, those with containers running (--all includes them) and those with uncommitted work in a worktree (--force discards it). It asks first; --yes skips the question and --dry-run shows the list and stops. The shared clones, the proxy and the installed multiverses are left alone, and a branch a universe started is deleted only when every commit on it is elsewhere.multiversectl system prune --all --yes
universe doctor [universe]Check the host, the multiverse and optionally a universe; exits 1 on any failure.multiversectl universe doctor 3
universe exec <universe> <app> -- <cmd>Run a command in a running container of a universe. --service picks one when the app has several. Streams straight to your terminal.multiversectl universe exec 3 api --service db -- psql -U postgres
universe run <universe> <app> -- <cmd>Run a command in a fresh one-off container instead, for a task that should not need the service up — a migration, a shell on a stopped app.multiversectl universe run 3 api -- python manage.py migrate
universe env <universe>Print a universe's environment as export lines for your shell.eval "$(multiversectl universe env 3)"
system proxy up|down|statusStart, stop, or inspect the shared proxy and its network. Universes keep their data when it stops.multiversectl system proxy status
init [owner/repo | url | path]Set up this machine's root catalog. It says what the machine already has, offers to keep it, and checks it is a Catalog and tagged with the topic multiversectl-catalog. On a machine with nothing it searches your GitHub and GitLab repositories for a tagged root, or takes an existing repository or path, a new private repository (--create, under any account you choose) or a local git repository (--local). It refuses to switch roots while multiverses installed from the current one exist; system reset first.multiversectl init --create multiverse-index
self-updateReplace this binary, and the web view beside it, with the latest release, and restart the web view if it is running. Commands run in a terminal end with a line on stderr when a newer release is out, with how many fixes it brings; the look is made in the background at most every 30 minutes, so it shows from the second command on. MULTIVERSECTL_NO_UPDATE_CHECK=1 turns it off. The web view shows the same as a banner.multiversectl self-update
versionPrint version, commit, build date and Go version.multiversectl version
agents skill install|uninstall|status|showinstall writes a short skill for Claude Code to ~/.claude/skills/multiversectl/SKILL.md (--project for this folder's .claude/skills, --dir for another). It tells an agent how to discover the tool (--json), to work in a universe of its own and leave a note and PR on it, and what to ask about first: other universes, prune, system reset, secrets, the shared proxy. The file records the version that wrote it and any newer multiversectl rewrites its own copies, so an upgrade never leaves an agent on old advice; a file it did not write is never touched. status says where it is and whether it is current, show prints it.multiversectl agents skill install
completion [shell]Install shell completions for bash, zsh or fish under your home directory, after asking (--yes skips; --shell overrides $SHELL; --uninstall removes them). With a shell's name, including powershell, prints the script instead. An installed script records the version that wrote it, and any later run of multiversectl rewrites it when the version has changed. Multiverse names and catalog paths complete from what is already on this machine, with no network.multiversectl completion --yes

In --help the commands are grouped: universe management, tool initialization, and catalog management. Run with no command, multiversectl shows the help and, on a machine with nothing installed, the two ways to begin.

Global flags: -f, --manifest path to the manifest; -m, --multiverse which installed multiverse to act on (default: the one whose folder you are in, else the only one installed); --root multiverse root (default $MULTIVERSECTL_ROOT, the manifest's spec.root, the saved config, or the manifest's directory); --no-color; -v, --verbose says what is being done (-v the steps and what the commands print, -vv the commands run, -vvv how each ended); --json machine-readable output on any command (--less for the least, --full with --help for every command) (see agents). <universe> is a positive integer.
