Every command

Everything that acts on a universe lives under universe, which u shortens: multiversectl u new 3 is multiversectl universe new 3. Everything about which projects exist and which are on this machine lives under catalog: with no subcommand it shows the tree. init, doctor, proxy, self-update and version stay at the top level. A command's aliases are listed beside it in multiversectl --help.

CommandWhat it doesExample
catalog [node-path]Show the catalog as a tree, or the part under a node. Workspaces already installed are marked, and a layer that cannot be read is listed as unavailable with the reason. --fetch refreshes first, -o json is for scripts, --from shows another catalog.multiversectl catalog acme/backend
catalog add <owner/repo | url | path>Put a project in the catalog, in the place you pick: a repository with a catalog.yaml is linked as a catalog, one with only a multiverse.yaml as a workspace; a local checkout is added by its origin; a manifest file goes into a repository (--same-repo, --repo, --new-repo). Where to put it is asked, with the repository each choice writes to; --at names it, --yes means the root.multiversectl catalog add acme/multiverse
catalog create <name>Create an empty catalog to group projects under: in the parent's repository (--same-repo), an existing one (--repo) or a new private one (--new-repo).multiversectl catalog create acme --new-repo acme-index
catalog rm <path>Remove an entry from the catalog that holds it. What it points at is untouched, and a workspace installed from it stays installed.multiversectl catalog rm acme/billing
catalog install [source ...]Put a project on this machine. A source is read in this order, and what it was taken for is said: a node in your catalog (a workspace, or everything under a catalog), a path, a git URL, then owner/repo. A repository with a catalog is read as one, so no root catalog is needed. With no source it shows your catalog to pick from. --base, --root, --name, --all, --fetch.multiversectl catalog install acme/multiverse
catalog uninstall <workspace>Forget a workspace; its files stay on disk. Takes the name or the catalog path.multiversectl catalog uninstall billing
catalog use <workspace>Make a workspace the one commands act on by default. Takes the name or the catalog path; -w does the same for one command.multiversectl catalog use acme
catalog statusThe root catalog, the workspaces installed here, and what has drifted: a manifest behind its remote, repositories not cloned, an entry the catalog dropped or repointed. Offline unless --fetch; -o json is for scripts.multiversectl catalog status --fetch
catalog update [workspace ...]Fetch the catalogs, fast-forward each workspace's manifest from where it was installed, and clone the repositories the new manifest lists. Refuses a manifest with local changes.multiversectl catalog update
universe new <number|name>Create a universe: one worktree per repo, secrets and state. Alias create. A universe is numbered or named after a branch. --branch (repeatable) overrides the branch: a bare name for every repo, repo=branch for one. --note records why it exists.multiversectl universe new fix/login
universe up <universe> [app ...]Start a universe, all apps or only those named. --with adds optional service groups. Alias start.multiversectl universe up 3 api --with workers
universe down <universe> [app ...]Stop a universe; keeps data and checkouts. Alias stop.multiversectl universe down 3
universe rm <universe>Destroy a universe: worktrees, containers, volumes and state. Asks first; --yes skips. Aliases remove, destroy.multiversectl universe rm 3 --yes
universe lsList universes: a table per universe with a row per app — its branch, its worktree on disk, its service, host and URL — and a row for every repository checked out with no services of its own. -o wide swaps the addresses for every service of every app — what is on, what is off and why, and which host ports it publishes — followed by an on disk block naming each repository's worktree, runtime project and volumes. -o list is one line per universe. The three combine with commas. Alias list.multiversectl universe ls -o wide
universe statusOne line per universe: whether it is running, partial, stopped or only created, how many of its services are up, when it was last started, its branches and note. ls has the detail per app.multiversectl universe status
universe urls <universe>Print a universe's URLs, one per line.multiversectl universe urls 3
system [--prune]Across every installed workspace (-w narrows it to one): how many universes each has, how many containers run, and how many hold uncommitted work. --prune removes universes as universe rm does, and keeps, saying why, those with containers running (--all includes them) and those with uncommitted work in a worktree (--force discards it). It lists what it will remove and asks; --yes skips the question. Shared clones and their branches, the proxy and the installed workspaces are left alone.multiversectl system --prune --all --yes
doctor [N]Check the host, the workspace and optionally a universe; exits 1 on any failure.multiversectl doctor 3
universe exec <universe> <app> -- <cmd>Run a command in a running container of a universe. --service picks one when the app has several. Streams straight to your terminal.multiversectl universe exec 3 api --service db -- psql -U postgres
universe run <universe> <app> -- <cmd>Run a command in a fresh one-off container instead, for a task that should not need the service up — a migration, a shell on a stopped app.multiversectl universe run 3 api -- python manage.py migrate
universe env <universe>Print a universe's environment as export lines for your shell.eval "$(multiversectl universe env 3)"
proxy up|down|statusStart, stop, or inspect the shared proxy and its network. Universes keep their data when it stops.multiversectl proxy status
init [owner/repo | url | path]Set up this machine's root catalog: an existing repository or path (checked; a repository with no catalog gets one), a new private repository via gh (--create), or a local git repository (--local). Pointing it at another source replaces the root, after asking.multiversectl init --create multiverse-index
self-updateReplace this binary with the latest release.multiversectl self-update
versionPrint version, commit, build date and Go version.multiversectl version
completion [shell]Install shell completions for bash, zsh or fish under your home directory, after asking (--yes skips; --shell overrides $SHELL; --uninstall removes them). With a shell's name, including powershell, prints the script instead. An installed script records the version that wrote it, and any later run of multiversectl rewrites it when the version has changed. Workspace names and catalog paths complete from what is already on this machine, with no network.multiversectl completion --yes

In --help the commands are grouped: universe management, tool initialization, and catalog and project management. Run with no command, multiversectl shows the help and, on a machine with nothing installed, the two ways to begin.

Global flags: -f, --manifest path to the manifest; -w, --workspace which recorded workspace to act on; --root workspace root (default $MULTIVERSECTL_ROOT, the manifest's spec.root, the saved config, or the manifest's directory); --no-color; -v, --verbose shows the commands being run. <universe> is a positive integer.
