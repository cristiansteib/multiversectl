Every command

CommandWhat it doesExample
bootstrap <manifest>Set up a workspace: record it, clone its repos, run doctor. Takes a path or a git URL. --name sets the name it is recorded under (default: from the root directory); other recorded workspaces are kept.multiversectl bootstrap ./multiverse.yaml --root ~/acme
workspacesList the workspaces bootstrapped on this machine; * marks the current one.multiversectl workspaces
use <workspace>Make a workspace the one commands act on by default. -w overrides it for a single command.multiversectl use acme
initSet up this machine's root catalog in an existing repository, a new private one (via gh), or locally. --repo, --create, --local, --public, --name, --yes.multiversectl init --create multiverse-index
add <owner/repo | url>Join a project: a repository with a catalog.yaml is linked as a catalog, one with only a multiverse.yaml is listed as a workspace. owner/repo means GitHub. Runs init first when there is no root catalog. --install, --at, --name, --ref, --path, --yes.multiversectl add fichero-app/multiverse --install
install [path ...]Set up workspaces from the catalog: a workspace, or everything under a catalog. Asks when no path is given. --base, --sync, --yes.multiversectl install acme
uninstall <workspace>Forget a workspace; its files stay on disk.multiversectl uninstall acme-api
catalog use <git-url-or-file>Record this machine's root catalog: an index of workspaces and of other catalogs, kept in a git repository or a file.multiversectl catalog use git@github.com:me/multiverse-index.git
catalog tree [source]Show the catalog as a tree. A layer that cannot be read (no access, a bad file) is listed as unavailable and the rest still shows.multiversectl catalog tree
catalog syncFetch every repository the root catalog refers to and report what is unavailable.multiversectl catalog sync
catalog create <name>Create a catalog inside another: in the parent's repository (--same-repo), an existing one (--repo) or a new private one (--new-repo). --at names the parent, / is the root; asked when omitted.multiversectl catalog create acme --new-repo acme-index
catalog add workspace <repo>List a repository's manifest in a catalog. --at, --name, --ref, --path.multiversectl catalog add workspace git@example.test:acme/api.git --at acme
catalog add catalog <repo>Link a catalog kept in another repository. It is checked first.multiversectl catalog add catalog git@example.test:acme/index.git --at /
catalog rm <path>Remove an entry from the catalog that holds it; what it pointed at is untouched.multiversectl catalog rm acme/api
new <number|name>Create a universe: one worktree per repo, secrets and state. Alias create. A universe is numbered or named after a branch. --branch (repeatable) overrides the branch: a bare name for every repo, repo=branch for one. --note records why it exists.multiversectl new fix/login
up <universe> [app ...]Start a universe, all apps or only those named. --with adds optional service groups. Alias start.multiversectl up 3 api --with workers
down <universe> [app ...]Stop a universe; keeps data and checkouts. Alias stop.multiversectl down 3
rm <universe>Destroy a universe: worktrees, containers, volumes and state. Asks first; --yes skips. Aliases remove, destroy.multiversectl rm 3 --yes
lsList universes: a table per universe with a row per app — its branch, its worktree on disk, its service, host and URL — and a row for every repository checked out with no services of its own. -o wide swaps the addresses for every service of every app — what is on, what is off and why, and which host ports it publishes — followed by an on disk block naming each repository's worktree, runtime project and volumes. -o list is one line per universe. The three combine with commas. Alias list.multiversectl ls -o wide
urls <universe>Print a universe's URLs, one per line.multiversectl urls 3
doctor [N]Check the host, the workspace and optionally a universe; exits 1 on any failure.multiversectl doctor 3
exec <universe> <app> -- <cmd>Run a command in a running container of a universe. --service picks one when the app has several. Streams straight to your terminal.multiversectl exec 3 api --service db -- psql -U postgres
run <universe> <app> -- <cmd>Run a command in a fresh one-off container instead, for a task that should not need the service up — a migration, a shell on a stopped app.multiversectl run 3 api -- python manage.py migrate
env <universe>Print a universe's environment as export lines for your shell.eval "$(multiversectl env 3)"
proxy up|down|statusStart, stop, or inspect the shared proxy and its network. Universes keep their data when it stops.multiversectl proxy status
updateReplace this binary with the latest release.multiversectl update
versionPrint version, commit, build date and Go version.multiversectl version

Global flags: -f, --manifest path to the manifest; -w, --workspace which recorded workspace to act on; --root workspace root (default $MULTIVERSECTL_ROOT, the manifest's spec.root, the saved config, or the manifest's directory); --no-color; -v, --verbose shows the commands being run. <universe> is a positive integer.
