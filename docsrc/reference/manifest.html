A project used to be called a workspace. Files and settings that say so are still read, and what multiversectl writes uses the new name:

PROJECT in universe lsCOMPOSE, the compose project name: project now means one thing

One multiverse.yaml lists the repositories and how a universe is addressed. It never describes containers; those stay in each repository's own compose files. The format is versioned, Kubernetes-style: apiVersion: multiverse/v1alpha1, kind: Project.

apiVersion: multiverse/v1alpha1
kind: Project
metadata:
  name: acme
spec:
  expose: lan
  domain: auto
  repos:
    - name: api
      url: git@github.com:acme/api.git
    - name: web
      url: git@github.com:acme/web.git

That is a complete project. A repository no apps entry names gets an app of its own name, so apps: is only for changing a default or splitting one repository into several apps.

Every field, with its meaning and default, is in schema/project.v1alpha1.yaml. That file is generated from the Go types by make schema; see also the commented examples/multiverse.yaml. The main keys:

KeyMeaning
metadata.nameNames the project; prefixes every compose project (acme-u3-api).
spec.rootWhere clones and universes live. --root and $MULTIVERSECTL_ROOT override it.
spec.exposeWho can reach a universe: lan (default) or local. Decides both the interface the proxy publishes on and what auto derives — see Networking.
spec.domainWildcard domain for hostnames. Default auto, which follows expose.
spec.branchBranch template for a numbered universe; {{universe}} expands to the number. Default u{{universe}}. A named universe uses its own name.
spec.proxyProxy network and named entrypoints (web on 80 by default).
spec.repos[]name, url, dir, runtime (compose or none).
spec.apps[]name, repo, compose, profiles, services, optional, secrets, publish, overlay, hosts, build.
spec.env[]Variables exported into every runtime call; {{uid}}, {{gid}} and ${VAR} expand.

hosts: for repositories you cannot change

Labels are the better place to say how a service is reached. hosts: on an app wins over them and exists for repositories you cannot edit:

hosts:
  - name: api            # api-u3.<domain>
    service: web
    port: 8001
    entrypoint: devapi    # default: web
    alsoMatch: [app, adm]  # other host keys, same service

portForward: reachable by IP and port

A client that refuses plain http to a hostname (an iPhone app) needs an address it may call. portForward on an app lists host keys, from the manifest, labels or the single exposed port, that are also published on a free host port:

apps:
  - name: api
    repo: api
    portForward: [api]    # http://<this machine's address>:<free port>

The kernel picks the port once; it is kept in the universe's state, so the address survives restarts, and no other universe gets it. It binds like the proxy: every interface with expose: lan, loopback only with expose: local. universe ls shows it as <host>:forward. The same thing can be asked from a compose label, multiverse.host.api.portForward: auto.
