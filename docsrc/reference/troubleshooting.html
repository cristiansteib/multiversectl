A universe runs old code, or a label that exists is not found

up says service "mailpit" exposes 2 ports, so which one serves api is a guess — add a label, yet the compose file on main has that label. A universe's checkouts keep the commit they were made from and do not follow main. When that may be the cause, the error ends with this universe's code is out of date and names the repositories and how far behind they are.

$ multiversectl universe sync 1
$ multiversectl universe up 1

sync never touches uncommitted changes, and leaves the universe's own commits alone unless --merge. universe status and the web page warn when a universe is behind; project update keeps the clones current.

Hostnames do not resolve

doctor warns: does not resolve; a router or local DNS server may be stripping private-IP answers. Some routers and resolvers drop DNS answers that point to private addresses. Compare your resolver with a public one:

$ dig +short app-u3.192-168-1-20.traefik.me
$ dig +short app-u3.192-168-1-20.traefik.me @1.1.1.1

Empty from the first and an address from the second means your resolver strips it. Allow private answers for that domain (often called DNS rebinding protection), point the device at another resolver, or use a domain you own.

Port 80 or 8001 is already in use

doctor fails with entrypoint web needs port 80, which is taken by another process when the proxy is not running yet. Find the owner and stop it:

$ ss -ltnp 'sport = :80'
$ multiversectl universe doctor

Or move the entrypoint in the manifest (spec.proxy.entrypoints); urls then prints the port.

A secret file is missing

up stops and names each missing file and where it belongs; doctor 3 fails with secret <app>: missing <path>. Files under an app's secrets: are copied from the clone into each universe, and a tracked .env.example is used when the clone has none. Otherwise put the file in the clone and start again:

$ cp .env ~/acme/api/.env
$ multiversectl universe up 3
$ multiversectl universe doctor 3

A dev server answers 403

Many dev servers reject Host headers they do not know, and a universe answers on app-u3.<domain>. Allow it with the variable the manifest passes in, through an inline overlay — the variable name is whatever your server reads:

apps:
  - name: web
    repo: web
    overlay:
      services:
        app-dev:
          environment:
            ALLOWED_HOSTS: "${APP_HOST}"

Also check that the hostname is the one multiversectl universe urls 3 prints, and that the service has the label or the single port that routes it.
