Ready-made binaries

$ curl -fsSL https://raw.githubusercontent.com/cristiansteib/multiversectl/main/install.sh | sh
# linux/darwin, amd64/arm64; set MULTIVERSECTL_VERSION to pin a release
$ mise use -g ubi:cristiansteib/multiversectl

Download the .deb from the releases page, then:

$ sudo dpkg -i multiversectl_*.deb

The script and the .deb also install a short alias, mvctl, and the web view, multiversectl-server, beside the command (see the web view). mise installs the command line only: multiversectl server needs the other program on the PATH, so use the script if you want it. Later: multiversectl self-update replaces both with the latest release.

From source

Go 1.27 or newer:

$ git clone https://github.com/cristiansteib/multiversectl
$ cd multiversectl && make install   # builds into ~/.local/bin

make install honours PREFIX, so make install PREFIX=/usr/local/bin puts it on the system path instead.

Remove it, completely

$ multiversectl cleanup

It lists everything multiversectl has put on the machine and removes none of it: the web server and shared proxy if they are running, each universe with the containers, volumes and worktrees it owns, the clones of your repositories, branches left by universes that are gone, the configuration and caches, shell completions, and the programs. Each item has its size and its removal command, and what would lose work that exists nowhere else, such as uncommitted changes, commits on no remote or a volume's data, is marked. The commands come last, in the order that is safe: stop what is running, remove the universes, then the clones and the configuration, and the programs at the end. --script prints only the commands, to read and run.

Run it before reset: once a project is forgotten the tool no longer knows its folder, so the clones and universes of a project you already reset are not listed. The root catalog's repository on GitHub or GitLab is not touched; delete it yourself if you want it gone.

Shell completions

$ multiversectl completion

It finds your shell from $SHELL, says which files it will write, and asks. --yes answers for you, which is what a setup script wants. Everything goes under your home directory; nothing needs root.

  • bash: ~/.local/share/bash-completion/completions/multiversectl, loaded on demand by the bash-completion package.
  • fish: ~/.config/fish/completions/multiversectl.fish, which fish loads by itself.
  • zsh: ~/.local/share/multiversectl/completions/multiversectl.zsh, plus a block between two marker comments in ~/.zshrc that sources it. Nothing puts a user directory on zsh's $fpath, so the startup file has to.

The first line of the installed file records the version that wrote it. After an upgrade, whether by self-update, a package or make install, the next run of any command rewrites a script written by another version, so completions follow the binary. It only updates a script that is already there; it never installs one you did not ask for. multiversectl completion --uninstall removes the file and the block.

What it needs on the machine

  • A container runtime with docker compose v2. On macOS that is Docker Desktop, OrbStack or Colima; on Linux, Docker Engine or Podman.
  • git, new enough for git worktree.
  • Nothing else. multiversectl runs no daemon of its own; the only long-lived process it starts is the shared proxy, and that is a container.

multiversectl universe doctor checks all of it and names what is missing.

Releases are built for Linux and macOS, on Intel (amd64) and Apple silicon or ARM (arm64). The script puts the programs in ~/.local/bin, which macOS does not have on its PATH by default: it warns when that is so. Shell completions work for zsh, the macOS default, and fish; bash on macOS is version 3.2 and has no bash-completion to load them.
