Before you start

You need a container runtime with docker compose, git, and a multiverse.yaml (a path or a git URL).

Your first universe

# record the project and clone its repos
$ multiversectl project install ./multiverse.yaml --root ~/acme
# universe 1: a worktree of every repo
$ multiversectl universe new 1
# start its containers
$ multiversectl universe up 1
# list universes and their state
$ multiversectl universe ls
# print the hostnames universe 1 answers on
$ multiversectl universe urls 1
# check the host, the project and universe 1
$ multiversectl universe doctor 1
# stop and delete universe 1 (asks first)
$ multiversectl universe rm 1

Seeing what you have

Run multiversectl --help for every command and flag. ls -o wide adds every service, whether it is up and the volumes it owns; -o list is one line per universe, for piping. They combine: -o list,wide.

A second universe

The point of the tool is the next command, not the first one. Create another universe and the first keeps running:

$ multiversectl universe new fix/login
$ multiversectl universe up fix/login
$ multiversectl universe ls

Both serve at once, on different hostnames, with their own containers, their own databases and their own checkouts. Nothing was stopped and no port was reassigned — Networking explains why they do not collide.
