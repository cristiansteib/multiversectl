Commands

Every command, what it does and the arguments it takes.

Every command

CommandWhat it doesExample
catalog [node-path]Show the catalog as a tree, or the part under a node. Workspaces already installed are marked, and a layer that cannot be read is listed as unavailable with the reason. --fetch refreshes first, -o json is for scripts, --from shows another catalog.multiversectl catalog acme/backend
catalog add <owner/repo | url | path>Put a project in the catalog, in the place you pick: a repository with a catalog.yaml is linked as a catalog, one with only a multiverse.yaml as a workspace; a local checkout is added by its origin; a manifest file goes into a repository (--same-repo, --repo, --new-repo). Where to put it is asked, with the repository each choice writes to; --at names it, --yes means the root.multiversectl catalog add acme/multiverse
catalog create <name>Create an empty catalog to group projects under: in the parent's repository (--same-repo), an existing one (--repo) or a new private one (--new-repo).multiversectl catalog create acme --new-repo acme-index
catalog rm <path>Remove an entry from the catalog that holds it. What it points at is untouched, and a workspace installed from it stays installed.multiversectl catalog rm acme/billing
install [source ...]Put a project on this machine. A source is read in this order, and what it was taken for is said: a node in your catalog (a workspace, or everything under a catalog), a path, a git URL, then owner/repo. A repository with a catalog is read as one, so no root catalog is needed. With no source it shows your catalog to pick from. --base, --root, --name, --all, --fetch.multiversectl install acme/multiverse
uninstall <workspace>Forget a workspace; its files stay on disk. Takes the name or the catalog path.multiversectl uninstall billing
use <workspace>Make a workspace the one commands act on by default. Takes the name or the catalog path; -w does the same for one command.multiversectl use acme
statusThe root catalog, the workspaces installed here, and what has drifted: a manifest behind its remote, repositories not cloned, an entry the catalog dropped or repointed. Offline unless --fetch; -o json is for scripts.multiversectl status --fetch
update [workspace ...]Fetch the catalogs, fast-forward each workspace's manifest from where it was installed, and clone the repositories the new manifest lists. Refuses a manifest with local changes.multiversectl update
new <number|name>Create a universe: one worktree per repo, secrets and state. Alias create. A universe is numbered or named after a branch. --branch (repeatable) overrides the branch: a bare name for every repo, repo=branch for one. --note records why it exists.multiversectl new fix/login
up <universe> [app ...]Start a universe, all apps or only those named. --with adds optional service groups. Alias start.multiversectl up 3 api --with workers
down <universe> [app ...]Stop a universe; keeps data and checkouts. Alias stop.multiversectl down 3
rm <universe>Destroy a universe: worktrees, containers, volumes and state. Asks first; --yes skips. Aliases remove, destroy.multiversectl rm 3 --yes
lsList universes: a table per universe with a row per app — its branch, its worktree on disk, its service, host and URL — and a row for every repository checked out with no services of its own. -o wide swaps the addresses for every service of every app — what is on, what is off and why, and which host ports it publishes — followed by an on disk block naming each repository's worktree, runtime project and volumes. -o list is one line per universe. The three combine with commas. Alias list.multiversectl ls -o wide
urls <universe>Print a universe's URLs, one per line.multiversectl urls 3
doctor [N]Check the host, the workspace and optionally a universe; exits 1 on any failure.multiversectl doctor 3
exec <universe> <app> -- <cmd>Run a command in a running container of a universe. --service picks one when the app has several. Streams straight to your terminal.multiversectl exec 3 api --service db -- psql -U postgres
run <universe> <app> -- <cmd>Run a command in a fresh one-off container instead, for a task that should not need the service up — a migration, a shell on a stopped app.multiversectl run 3 api -- python manage.py migrate
env <universe>Print a universe's environment as export lines for your shell.eval "$(multiversectl env 3)"
proxy up|down|statusStart, stop, or inspect the shared proxy and its network. Universes keep their data when it stops.multiversectl proxy status
init [owner/repo | url | path]Set up this machine's root catalog: an existing repository or path (checked; a repository with no catalog gets one), a new private repository via gh (--create), or a local git repository (--local). Pointing it at another source replaces the root, after asking.multiversectl init --create multiverse-index
self-updateReplace this binary with the latest release.multiversectl self-update
versionPrint version, commit, build date and Go version.multiversectl version
completion <shell>Print a shell completion script. Workspace names and catalog paths complete from what is already on this machine, with no network.multiversectl completion zsh

In --help the commands are grouped: universe management, tool initialization, and catalog and project management. Run with no command, multiversectl shows the help and, on a machine with nothing installed, the two ways to begin.

Global flags: -f, --manifest path to the manifest; -w, --workspace which recorded workspace to act on; --root workspace root (default $MULTIVERSECTL_ROOT, the manifest's spec.root, the saved config, or the manifest's directory); --no-color; -v, --verbose shows the commands being run. <universe> is a positive integer.
