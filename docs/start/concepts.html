Concepts at a glance

The five words this documentation uses — multiverse, universe, app, host and entrypoint — and how they fit together.

Five words

WordWhat it means
MultiverseThe definition, one multiverse.yaml: the repositories it is made of, the apps that run them, and how a copy of it is addressed. A repository can define several, one file each. Kept wherever you like and used from anywhere with -m or -f. A catalog is only an index of multiverses; it defines nothing.
UniverseOne complete copy of that multiverse: a git worktree of every repository, one compose project per app, and its own set of hostnames. Numbered (3) or named after a branch (fix/login).
AppA runnable unit inside a universe: one repository's compose files, started as their own compose project. A repository usually has exactly one, and does not have to say so.
HostOne address an app answers on, named by a key: host api in universe 3 is api-u3.<domain>. A host knows which service and container port serve it.
EntrypointA port the shared proxy listens on, named. Every universe shares them, because requests are told apart by hostname rather than by port.

How they nest

multiverse "acme"            multiverse.yaml
├── universe 3               ~/acme/universes/3
│   ├── app api              compose acme-u3-api
│   │   ├── service web      host api  → api-u3.example.test
│   │   └── service db       no host; reachable inside the app
│   └── app web              compose acme-u3-web
│       └── service app-dev  host app  → app-u3.example.test
└── universe fix/login       ~/acme/universes/fix-login
    └── ...                  the same shape, its own everything

Each level namespaces the one below: multiverse, universe, app. A container is acme-u3-api-web-1, so two repositories can both call a service app without meeting.

It is not a virtual machine

A universe is a namespace, not a sandbox. It shares the kernel, the runtime, the image cache and the git object store — which is why a new one costs seconds and the second does not double your disk use — and keeps apart the four things that collide: checkouts, container names, volumes and hostnames.

So it is not isolated for security: anything in one universe can reach another's containers over the proxy network. And it is not reproducible the way an image is — it is your machine, with your daemon and your caches.
