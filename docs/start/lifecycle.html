Life of a universe

What exists after new, up, down and rm, what each of them keeps, and the order up does its work in.

Drive it yourself

One multiverse of three repositories — ui (react, hot reload), k8s-manifest (nothing to run) and api (http, db, redis) — run twice. The boxes are drawn from the start; what they hold is made by the commands. Press Enter, or use run, to run the command waiting at the prompt.

    The same four steps, as a table
    
  
    A universe has a short life and only four commands change it. The one worth knowing cold is the difference between down, which you will run every day, and rm, which you run once and cannot undo.
    
  

    


    
  
    The commands
    
  
    
  
    CommandWhat it doesWhat it keeps
    
  
    start <source>From nothing to something running: installs the multiverse, creates a universe if there is none, starts it, prints its addresses.A multiverse already installed is used as it is.
    
  
    universe new [name]One worktree per repository on a branch that exists nowhere yet, secrets copied in from the clone, state written. Nothing is started.Refuses rather than touch a branch that already exists.
    
  
    universe checkout <branch>The same, on a branch that already exists — to work on it or review it.Removing the universe later never deletes the branch.
    
  
    universe up <universe>Starts it: see the order below. All apps, or only the ones you name.Everything on disk. Safe to run again at any time.
    
  
    universe sync [universe]Fetches and moves each checkout forward, where that loses nothing, so a universe made last week has this week's main in it.A checkout with uncommitted changes or commits of its own is left alone.
    
  
    universe down <universe>Takes the containers and the app networks away, and frees the memory they held.Volumes, worktrees, state. up picks up where you left off.
    
  
    universe rm <universe>Destroys the universe: worktrees, containers, volumes, state. It prints what it will do and asks for the universe's name typed back.Branches, so committed work survives. Uncommitted work in a worktree stops the removal until --force.
    
  
    
  
    Every command and flag is in Commands.
    

    


    
  
    What up does, in order
    
  
    Worth knowing because it says where a failed start stopped, and what it had already done.
    
  
      
    
    1. Checks the secrets, starts the proxyBefore anything else, so a missing file leaves nothing half started. The shared proxy is started if it is not already running.
      2. 
    
    2. Reads the addresses from your compose filesLabels can have changed since the universe was made, so the host rules are resolved again and kept with the universe.
      3. 
    
    3. Renders the files an app reads at bootConfig written from this universe's own values, before the containers that read it exist.
      4. 
    
    4. Writes the generated fragmentProxy labels, the dropped published ports and the variables asked for by label, in a file beside your checkouts. Your own compose files are not touched.
      5. 
    
    5. Builds and startsImages are built if the app asks for it, then compose brings the services up.
      6. 
    
    6. Connects the proxy to the app's networkThe network exists only now, so this is the first moment the address can answer.
      7. 
    
    7. Waits, then runs the hooksUntil the services with a healthcheck are healthy and the hosts that set ready answer — so a hook that needs the app to respond can rely on it.
      8. 
  
    
  
    Apps are independent: one that cannot start does not keep the others from it. The summary at the end says which are up and which failed, and the exit status is non-zero.
    

    


    
  
    Living with several
    
  
    The cost of a running universe is its containers' memory, so the usual rhythm is a handful created and one or two up. universe status is one line each; universe ls is every address.
    
  
    $ multiversectl universe status
UNIVERSE    STATE     SERVICES  LAST STARTED  BRANCHES
1           running   5/5       2 hours ago   feat/login
2           stopped   0/5       yesterday     main
fix/cart    created   0/5       never         fix/cart
    
  
    A universe you are done with goes away with rm; system prune does the same across every multiverse on the machine, listing what it will remove and keeping back anything holding work that exists nowhere else. What's on your machine shows where all of it lives.
