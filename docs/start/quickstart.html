Quick start

Describe a multiverse, create a universe and open it — from nothing to two running copies of a multiverse.

Before you start

You need a container runtime with docker compose, git, and a multiverse.yaml (a path or a git URL).

Your first universe

$ multiversectl start ./multiverse.yaml
› universe 1: a worktree of every repository
› starting universe 1
✓ universe 1 is up
  http://api-u1.192-168-1-20.traefik.me

That is the whole of it: start installs the multiverse, makes universe 1 and starts it, and ends on an address to open. The source is anything start takes — owner/repo, a git URL, a path, or a node in your catalog. Run it again and it starts the universe that is already there; with several, -u names one; --open opens the first address in a browser.

The same thing as the steps it takes once the multiverse is installed, for when you want one of them on its own:

# universe 1: a worktree of every repo
$ multiversectl universe new 1
# start its containers
$ multiversectl universe up 1
# list universes and their state
$ multiversectl universe ls
# print the hostnames universe 1 answers on
$ multiversectl universe urls 1
# check the host, the multiverse and universe 1
$ multiversectl universe doctor 1
# stop and delete universe 1 (asks first)
$ multiversectl universe rm 1

Seeing what you have

ls is one block per universe: which app, on which branch, at which address.

$ multiversectl universe ls
universe 3  ·  acme-u3  ·  6 running  ·  192-168-1-20.traefik.me
─────────────────────────────────────────────────────────────────
APP    BRANCH  URL
admin  u3      http://adm-u3.192-168-1-20.traefik.me
api    u3      http://api-u3.192-168-1-20.traefik.me
api            http://devapi-u3.192-168-1-20.traefik.me:8001
api            http://mail-u3.192-168-1-20.traefik.me
web    u3      http://app-u3.192-168-1-20.traefik.me
mobile u3      checkout only, no services

A host that is also forwarded to a port shows that address beside it. ls -o wide is the rest: the service behind each address, what is up and what is off, what publishes a port, and every worktree, compose project and volume. -o list is one line per universe, for piping, and they combine: -o list,wide.

A second universe

The point of the tool is the next command, not the first. Create another and the first keeps running:

$ multiversectl universe new fix/login
$ multiversectl universe up fix/login
$ multiversectl universe ls

Both serve at once on different hostnames, with their own containers, databases and checkouts. Nothing was stopped and no port reassigned — Networking explains why.

The same thing in a browser

Everything above is also on a page — the catalog, the multiverses and every universe, live, with the same operations behind buttons.

$ multiversectl server start --open
$ multiversectl server stop

It runs in the background behind a token, and the two can be used together. Explore and run it in a browser has the rest.
