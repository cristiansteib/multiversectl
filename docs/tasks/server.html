Explore it in a browser

A read-only web view of the catalog tree, the workspaces installed here and the fleet of universes, with doctor on demand.

See the whole setup in a page

$ multiversectl server --open
✓ serving http://127.0.0.1:7777 (read-only; Ctrl-C stops it)

One page, three views, refreshed every ten seconds while it is open:

  • Overview: the root catalog, the workspaces installed here, and where each has drifted, as status shows it. Fetch remotes and compare is status --fetch.
  • Catalog: the tree, with what is installed marked and layers you cannot reach listed with the reason. Filter it by name, path or repository, and copy the install command for any workspace.
  • Fleet: every universe of every installed workspace, with its branches, its apps and the state of each service, its addresses as links, and the paths of its checkouts. Press / to filter. Doctor runs the checks for a workspace or a single universe.

Each workspace also has a page with its repositories, whether each is cloned, its apps and their hostnames, and the proxy entrypoints it needs.

What it will and will not do

It only reads. There is no way to start, stop, install or edit anything from the page; it shows the command instead, ready to copy, and the command line remains the place where things change.

It has no login, so it listens on the loopback address only and answers only requests addressed to localhost, 127.0.0.1 or ::1. That second check matters: without it, a web page on another site could point a name it controls at your machine and read your setup through the browser. --addr picks another loopback port (0 chooses a free one). --expose allows any address and any host name; use it only on a network you trust, because anyone who can reach the port can read the same pages.

The page loads nothing from outside, which its content security policy enforces, and builds everything from text, so a branch name or a note cannot inject markup.
