What it does, and what it is not

Everything it gives you, feature by feature, and the jobs it is the wrong tool for, with what to use instead.

What it does

FeatureWhat you getRead more
The whole system per copyEvery repository on its own branch, every app running, handled as one.Work across branches
Shared in one commandStart a whole system someone shares with one command, nothing to set up.Quick start
Hostnames, not portsEach copy gets its own addresses, so nothing collides.Networking
Open from any deviceOpen any copy from your phone or another computer on your network.Reach a universe
Logins that workEach copy tells its apps their own addresses, so logins and CORS work.Labels
HTTPSServe any copy over HTTPS, with your own certificate.Serving https
Your compose filesRuns the compose files you already have, unchanged.Labels
A database per copyEach copy has its own data. One branch never touches another's.Storage and data
HooksSeed data and set things up when a copy starts; clean up when it goes.Hooks
Config per copyConfig files written with each copy's own values.Render
SecretsYour local secret files, in every copy.Secrets
Start only what you needExtra services and apps run only when you ask for them.Optional
Branches kept currentBring every copy up to date with its branch in one step.Work across branches
Health checksCheck the machine and every address, and say what is wrong.Troubleshooting
A web viewSee and control every copy from a browser, a phone included.In a browser
CatalogsA shared list of systems your team can install.Catalogs
Made for agents tooGive a coding agent a whole copy of its own.Agents

What it is not

Knowing where it stops saves trying it for the wrong job.

It is notBecauseFor that, use
A sandbox or a VMUniverses share your kernel, daemon and user: one can fill the disk or reach another's containers through the runtime. They are copies you trust, not a boundary.A VM, or a container sandbox for untrusted code
A replacement for docker composeIt describes no containers. It reads your compose files and adds only routing and names, so they keep working without it.The compose files you have
A rebuild-on-save loopWhat reloads in a universe is what your compose files already do: a bind mount and a dev server.Your dev server; Tilt or Skaffold on Kubernetes
A deployment or production toolIt runs on one machine, for development. Nothing it does belongs on a server others depend on.Your deployment pipeline
A preview service on the internetA universe answers on this machine or its network, not to the outside world, and is made by you, not by CI.A preview-environment service
An agent runnerIt gives an agent a whole environment to work in; it does not start, prompt or supervise the agent.Your agent, or a worktree manager, pointed at a universe
A way to share one database among copiesEach universe runs its own services, data included. That keeps branches apart, and it is what the machine's memory has to hold.Fewer universes, or lighter services in an overlay

Compared with other tools puts it next to its neighbours, feature by feature, and says when each is the better choice.
