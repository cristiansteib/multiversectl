Install

One binary for Linux and macOS, from a script, mise, a .deb or source.

Ready-made binaries

$ curl -fsSL https://multiversectl.dev/install.sh | sh
# linux/darwin, amd64/arm64; set MULTIVERSECTL_VERSION to pin a release
$ brew install cristiansteib/tap/multiversectl

Or brew tap cristiansteib/tap once, then brew install multiversectl.

$ mise use -g ubi:cristiansteib/multiversectl

Download the .deb from the releases page, then:

$ sudo dpkg -i multiversectl_*.deb

The script, Homebrew and the .deb also install the alias mvctl and the web view, multiversectl-server, beside the command. mise installs the command line only, so multiversectl server then needs the other program on the PATH. multiversectl self-update replaces both with the latest release.

From source

Go 1.27 or newer:

$ git clone https://github.com/cristiansteib/multiversectl
$ cd multiversectl && make install   # builds into ~/.local/bin

make install honours PREFIX, so make install PREFIX=/usr/local/bin puts it on the system path instead.

Remove it, completely

$ multiversectl system footprint

It lists everything multiversectl has put on the machine — the server and proxy if running, every universe with its containers, volumes and worktrees, the clones, branches left behind, the configuration, caches, completions and the programs — and removes none of it. Each item has its size and its removal command, and anything that would lose work existing nowhere else is marked. The commands come last, in a safe order; --script prints only those.

Run it before system reset: once a multiverse is forgotten the tool no longer knows its folder. The root catalog's repository is not touched.

Checking what you downloaded

Every release publishes checksums.txt, and self-update verifies each file against it before replacing anything: a download that does not match is not installed, and a release without the list is not installed from either.

The list itself is signed, with a short-lived certificate tied to the workflow that built the release rather than to a key anyone could take, so you can check it yourself:

$ cosign verify-blob checksums.txt \
    --signature checksums.txt.sig --certificate checksums.txt.pem \
    --certificate-identity-regexp '^https://github.com/cristiansteib/multiversectl/' \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com
$ sha256sum -c checksums.txt --ignore-missing

Shell completions

$ multiversectl completion

It finds your shell from $SHELL, says which files it will write, and asks. --yes answers for you, which is what a setup script wants. Everything goes under your home directory; nothing needs root.

  • bash: ~/.local/share/bash-completion/completions/multiversectl, loaded on demand by the bash-completion package.
  • fish: ~/.config/fish/completions/multiversectl.fish, which fish loads by itself.
  • zsh: ~/.local/share/multiversectl/completions/multiversectl.zsh, plus a block between two marker comments in ~/.zshrc that sources it. Nothing puts a user directory on zsh's $fpath, so the startup file has to.

The installed file records the version that wrote it, and after any upgrade the next command rewrites it, so completions follow the binary. It only updates a script already there. completion --uninstall removes the file and the block.

What it needs on the machine

  • A container runtime with docker compose v2. On macOS that is Docker Desktop, OrbStack or Colima; on Linux, Docker Engine or Podman.
  • git, new enough for git worktree.
  • Nothing else: it runs no daemon of its own, and the only long-lived process it starts is the shared proxy, which is a container.

multiversectl doctor checks all of it and names what is missing.

Releases are built for Linux and macOS on amd64 and arm64. The script installs into ~/.local/bin, which macOS does not put on the PATH by default, and warns when it is missing. Completions work for zsh and fish; macOS ships bash 3.2 with no bash-completion to load them.
