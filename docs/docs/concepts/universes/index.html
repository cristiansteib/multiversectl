Universes

What a universe is made of, how it is named, and what it does and does not share with the others.

What a universe is made of

Four things on disk and nothing else:

  • A worktree of every repository, under <root>/universes/<id>/<repo>, on the universe's branch. Real directories, for your own editor and your own git.
  • A compose project per app, named <project>-<slug>-<app>, which namespaces containers, networks and volumes.
  • A set of hostnames, one per host key, resolved at creation and refreshed on every start.
  • A state file, universe.yaml, holding those plus when it was created, when it last started and why it exists.

Nothing git already has is copied: every worktree shares the clone's object store, so ten universes of a large repository cost ten checkouts, not ten histories.

Numbered or named

$ multiversectl universe new 3           # branch u3, hostnames api-u3.<domain>
$ multiversectl universe new fix/login   # branch fix/login, api-fix-login.<domain>

A universe is identified by the name you typed; everything else is derived from it.

Derived3fix/login
Directoryuniverses/3universes/fix-login
Slug, in hostnames and multiversesu3fix-login
Default branchspec.branch, u3 by defaultthe name itself

The slug is the name reduced to what DNS labels and compose projects both accept, so feat/ARCA-123 is reachable at api-feat-arca-123.<domain> while the branch keeps its real name. A name whose slug would not fit a DNS label is refused with the limit named, rather than truncated into a collision.

Commands take whichever of the three you are looking at: up fix/login, up fix-login, up 3 and up u3 all find their universe, and an unknown name lists the ones that exist.

Branches, and never clashing

A universe checks out one branch per repository, in one of two ways that never mix.

A universe is on one branch in every repository: checked out where it exists, started from the base where it does not. A numbered universe renders spec.branch; a named one uses its name:

spec:
  branch: dev/u{{universe}}   # default: u{{universe}}

Every repository is fetched and looked at first, so a branch someone pushed an hour ago counts. Where the branch already exists, in the clone or on origin, it is checked out as it is, tracking origin when it is only there; where it does not, it is started from origin/<base> as fetched, not from the clone's own copy, which is routinely behind. Each repository says which it got. So the same command starts a branch and picks one up to review or carry on. A branch already checked out in another universe or in the clone is refused, because git allows a branch in one worktree only, and the place is shown. If a later repository fails, what was added is taken back. --base starts new branches elsewhere; --branch names the branch, bare for every repository or repo=name for one.

$ multiversectl universe new                       # the next free number
$ multiversectl universe new fix/login             # checked out where it exists, started where not
$ multiversectl universe new 3 --base release/1.2
$ multiversectl universe new 3 --branch feat/invoicing --base api=release/1.2

The next free number steps over any number whose branch still exists in a repository, and says which it skipped and why — that is what a removed universe leaves behind when its branch held work that was nowhere else. Naming that number picks the branch, and its work, up again.

Removing a universe deletes only the branches it started, and only when nothing is lost — every commit already on the base or on the branch's own remote. One holding commits that are on no remote is kept, and rm says how to delete it yourself. A branch that already existed when the universe was made is never touched.

One thing at a time, whoever is asking

A terminal, the web view and an agent are separate programs, and none of them can see what the others are halfway through. So anything that changes a universe takes a lock in the multiverse first, and a second caller is told what has it rather than running alongside it:

$ multiversectl universe down 2
error: universe 2 is busy: pid 4242: multiversectl universe up 2 is working on it

Creating and removing lock the multiverse, because they change which universes exist and which numbers are free; starting, stopping, syncing and restarting lock only their own universe, so different universes still run side by side. The lock is the operating system's, so a command that is killed leaves nothing behind to clean up.

What a universe remembers

One left sitting for a week should still be identifiable, so the state file keeps more than the routing:

# ~/acme/universes/fix-login/universe.yaml
name: fix/login
id: fix-login
slug: fix-login
created: 2026-10-25T10:44:09Z
lastStarted: 2026-10-25T10:46:11Z
note: PR 412 review
manifest: /home/me/work/acme/multiverse.yaml
version: 0.0.1

Set the note when you create it and ls shows it beside the name; ls -o wide adds created 3d ago · last started 2h ago, which is usually how you pick one to reclaim.

$ multiversectl universe new fix/login --about "PR 412 review"

Lifecycle

CommandWhat changes
newWorktrees, secrets, state. Nothing starts. Safe to run again: checkouts are kept, and a repository added to the manifest since is added here.
upBrings up the shared proxy, regenerates the routing, starts each app. Idempotent.
downStops containers. Volumes and checkouts stay.
rmDestroys containers, volumes, worktrees and state. Asks for the universe's name typed back.
