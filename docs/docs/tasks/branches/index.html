Work across branches

Put a feature in its own universe, override one repository's branch, add a repository, and remove a universe when you are done.

Work on two branches at once

# a new universe: branches of its own, named after it
$ multiversectl universe new fix/login --about "PR 412 review"
$ multiversectl universe up fix/login
$ multiversectl universe urls fix/login
http://api-fix-login.10-0-0-5.traefik.me
# or number it (leave the number out for the next free one), and say where it starts
$ multiversectl universe new 2 --branch feat/invoicing --base api=release/1.2

Where the branch already exists it is checked out; where it does not it is started from the base. A numbered one takes its branch from spec.branch, u{{universe}} by default. Commands accept the name as typed, its directory or its slug. Each universe has its own containers, volumes and hostnames, so the two run side by side.

Review or continue a branch that already exists

$ multiversectl universe new fix/login
$ multiversectl universe new 7 --branch fix/login   # named 7, on fix/login

The same command: it checks out the branch you name in every repository that has it, locally or on origin, and a repository that lacks it gets a new branch of that name from its base. It refuses a branch checked out in another universe or in the clone, because git allows a branch in one worktree only. Removing the universe keeps the branch: only a branch a universe started is ever deleted.

Add a repository to a multiverse

# multiverse.yaml
spec:
  repos:
    - name: worker
      url: git@github.com:acme/worker.git

That is the whole change: a repository no apps entry names gets an app of its own name, its compose files are found by convention, every service they define starts, and the addresses come from their labels. Add an apps entry only to change one of those, or to split the repository into several apps.

# clone the new repo (already-cloned ones are skipped)
$ multiversectl catalog sync
# add its worktree to an existing universe; existing checkouts are kept
$ multiversectl universe new 3
$ multiversectl universe up 3 worker

A repository you only edit, with no compose file, needs nothing: it is checked out and nothing starts for it.

Remove a universe and its data

$ multiversectl universe rm 3
$ multiversectl universe rm 3 --yes     # skip the prompt

rm lists what it will destroy and asks you to type the number back. It removes the worktrees, the containers and volumes, so every database in it, and the directory and state file. The shared clones are untouched. To stop a universe and keep everything, use universe down 3.

Work that is only in a worktree is a second question, with its own answer: a universe holding uncommitted changes is refused, and named, until --force. Typing a universe's name back says "yes, this universe", not "yes, and the afternoon's work in it". --yes skips the question; it never discards.

A worktree a container has written into as root holds files you cannot delete, so that one is left where it is: everything else still goes, the universe stays listed, and the command says which paths to remove with sudo and to run rm again to finish. The same goes for a worktree the clone has lost its record of — the directory is taken away even though git will not do it.

Clear out every universe on the machine

$ multiversectl system prune --dry-run   # show what it would remove, and stop
$ multiversectl system prune             # the idle ones, asking first
$ multiversectl system prune --all --yes # everything, running included, no question

prune does what rm does, to every universe of every installed multiverse, or only the one named with -m. Two kinds are kept unless you say otherwise, each listed with the reason: one with containers running, until --all; one with uncommitted work, until --force. --yes only skips the question and never discards work.

It does not touch the clones, the proxy, or the installed multiverses and catalogs. Branches a universe started are deleted only when every commit on them is already on the base or on a remote; one holding anything else is kept and named.
