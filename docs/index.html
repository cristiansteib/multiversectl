multiversectl

Run your whole multi-repository system several times at once, on one machine. Each run gets its own branch, its own containers, its own data and its own hostnames — so several people, or several agents, can work different branches at the same time without taking turns.

Run your system several times at once

A universe is one running copy of your whole system: a git worktree of every repository, containers of its own, volumes of its own, hostnames of its own. Have as many as you like.

One universe per agent, on one machine

Give each coding agent a universe of its own and they work different branches, and different pull requests, at the same time — on the machine you already have. No second machine, no virtual machine, no cloud environment each: one Docker daemon, one image cache, one pool of CPU and memory, shared between them. It does not run the agents — it gives each one somewhere to run.

Agent-ready out of the box

No server and no protocol: an agent runs the command line, and one flag makes every command machine-readable — including its own help, so it can find its way without being told.

$ multiversectl --help --json          # every command and flag, as a document
$ multiversectl universe ls -o json    # the whole fleet, in few tokens
$ multiversectl agents skill install   # the skill, written for Claude Code
JSON on every command --json anywhere, --less for only what an agent must have. A skill, installed for you How to work in a universe of its own, and what never to do without asking. An AGENTS.md of its own Written into your multiverse's repository, saying what it is and how to run it.

And one page that shows them all

Work spread across several universes is work you cannot see. The web view lists every one of them live, with buttons for the same operations the CLI has.
